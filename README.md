# تطبيق جيب تاب | JAIB TAP (Prototype)

نموذج أولي تجريبي (Proof of Concept / Prototype) لتطبيق **جيب تاب (Jaib Tap)**، تم تصميمه وتطويره كنموذج عرض تقديمي لصالح **شركة عهد للخدمات المالية** (المطورة لمحفظة جيب في الجمهورية اليمنية).

يهدف النموذج لإثبات جدوى استخدام **ميداليات وملصقات NFC** لتسريع وتسهيل عمليات السحب النقدي، الإيداع، مساهمات "فرقتك"، ودفع المشتريات.

---

> [!IMPORTANT]
> **تنبيه الأمان والخصوصية:**
> - هذا التطبيق **نموذج تجريبي فقط (Prototype)** ولا ينفذ أي تحويلات مالية حقيقية ولا يتصل بخوادم أو محافظ جيب الحقيقية.
> - جميع العمليات والأرصدة وهمية ويتم حسابها وتخزينها محلياً على الجهاز.
> - قراءة شريحة **NTAG213** عبر الهاتف تثبت اكتشاف العلامة (UID) فقط، ولا تعتبر توثيقاً تشفيرياً مالياً آمناً في بيئة الإنتاج (موضح أدناه مسار الترقية إلى NTAG 424 DNA).

## 📱 التقنيات المستخدمة

- **اللغة:** Kotlin (Native Android)
- **الحد الأدنى للنظام:** Android 7.0 (API Level 24)
- **النظام المستهدف:** Android 14 (API Level 34)
- **واجهات المستخدم:** Native XML Layouts (مستوحاة بالكامل من الهوية البصرية الرسمية لتطبيق جيب: الخلفية الداكنة، واللون الأحمر القرمزي `#A81C2E`).
- **NFC API:** `android.nfc` لقراءة معرفات الشريحة وتحديد نوعها.
- **إدارة البيانات والحفظ:** محاكاة محلية مع التخزين التلقائي (`SharedPreferences` بصيغة JSON) لحفظ الأرصدة وسجل العمليات حتى بعد إغلاق التطبيق.

## 🛠 طريقة تشغيل المشروع وتوليد ملف APK

### 1. عبر Android Studio (الطريقة الموصى بها):
1. افتح **Android Studio**.
2. اختر **Open** ثم حدد مجلد المشروع:
   `C:\Users\KING\.gemini\antigravity\scratch\JaibTap`
3. انتظر انتهاء الـ Gradle Sync.
4. لتشغيل التطبيق على هاتفك:
   - قم بتوصيل هاتف Android يدعم NFC عبر كابل USB وفعل **تصحيح أخطاء USB (USB Debugging)**.

5. لإنشاء ملف APK للتثبيت اليدوي:
   - من القائمة العلوية: **Build** > **Build Bundle(s) / APK(s)** > **Build APK(s)**.
   - ستجد الملف الناتج في:
     `app/build/outputs/apk/debug/app-debug.apk`

### 2. عبر سطر الأوامر (Command Line):
```powershell
cd C:\Users\KING\.gemini\antigravity\scratch\JaibTap
.\gradlew.bat assembleDebug
```

## 💡 كيفية تعديل البيانات وربط ميداليات NFC حقيقية

### 1. تعديل البيانات التجريبية برمجياً:
افتح الملف:
[`app/src/main/java/com/jaibtap/app/data/MockCentralDatabase.kt`](file:///C:/Users/KING/.gemini/antigravity/scratch/JaibTap/app/src/main/java/com/jaibtap/app/data/MockCentralDatabase.kt)
يمكنك تعديل الأرصدة، الأسماء، الأرقام، حدود التفويض، أو إضافة مستخدمين جدد بكل سهولة.

### 2. تجربة ميدالية NFC حقيقية (Physical Tag):
- عند تقريب أي ميدالية أو ملصق NFC حقيقي (NTAG213 أو أي شريحة متوافقة) من الهاتف أثناء فتح شاشة NFC:
  1. يقوم التطبيق بقراءة الـ **UID** الفريد للشريحة وتحديد نوعها.
  2. إذا كانت الشريحة جديدة، يعرض التطبيق تلقائياً نافذة: **"هل تود ربط هذه الشريحة الفيزيائية بأحمد أو محمد؟"**.
  3. بمجرد اختيار الحساب، تصبح تلك الميدالية الحقيقية مفعلة ومعتمدة في هاتفك لجميع عمليات السحب والإيداع وفرقتك!

### 3. الاختبار بدون توفر شريحة NFC (Simulated Mode):
في أسفل شاشة NFC، توجد أزرار محاكاة:
- **ميدالية أحمد**
- **ميدالية محمد**
- **ميدالية غريبة (Unknown Tag)**
تتيح لك اختبار كافة سيناريوهات العرض أمام أي لجنة حتى لو لم يكن معك شريحة حقيقية وقت العرض.

## 🔐 حدود النموذج الأولي وما تحتاجه شركة عهد للإنتاج الحقيقي

عند الانتقال من النموذج التجريبي (Prototype) إلى مرحلة الإنتاج الفعلي (Production)، ينبغي لشركة عهد للخدمات المالية مراعاة الآتي:

1. **الترقية إلى شرائح NTAG 424 DNA:**
   - شريحة **NTAG213** المستخدمة في النموذج توفر معرّف UID ثابت يسهل نسخه (Cloning).
   - في الإنتاج الحقيقي، يجب اعتماد **NTAG 424 DNA** التي تدعم خوارزمية **SUN (Secure Unique NFC)** و **AES-128 Cryptography**. تولد الشريحة رمزاً تشفيرياً متغيراً في كل لمسة مع عداد داخلي (CMAC) يتم التحقق منه على خوادم شركة عهد لمنع التزوير تماماً.
2. **الربط مع السيرفر والـ API المالي:**
   - استبدال `DataManager.kt` المحلي باستدعاءات REST / gRPC مشفرة تتصل بالنظام المصرفي لمحفظة جيب عبر بروتوكول TLS 1.3 مع Certificate Pinning.
3. **رمز التفويض الديناميكي (Dynamic OTP / Tokenization):**
   - توليد رموز تفويض متغيرة عبر التطبيق أو الرسائل، أو عبر شريحة التشفير مباشرة، بدلاً من رمز التفويض الثابت.
